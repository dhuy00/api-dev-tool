# User Journeys

## Journey 1: Create and Validate a Request

1. The user opens a project.
2. The user creates or selects a request.
3. The user configures method, URL, headers, and body.
4. The user executes the request.
5. The user reviews status, response body, headers, and timeline.
6. The user saves a response example or updates the collection.

## Journey 2: Generate Payload Data

1. The user opens a request with a JSON body.
2. The user chooses the payload generation mode.
3. The user optionally selects fields, locale, or seed.
4. The user previews the generated payload.
5. The user applies the payload to the request.

## Journey 3: Generate Test Cases

1. The user opens an endpoint or request definition.
2. The user invokes automated test generation.
3. The system proposes a set of test cases.
4. The user reviews and executes a subset.
5. The user analyzes pass/fail results and updates the suite.

## Journey 4: Publish Documentation

1. The user selects a collection or project.
2. The system generates documentation sections.
3. The user applies manual edits where needed.
4. The user publishes or drafts the documentation site.
5. Teams consume the published documentation.

## Journey 5: Run a Sequential Workflow

1. The user opens a flow builder.
2. The user creates a login → create → update → delete sequence.
3. The user validates the flow.
4. The user runs the flow and examines node-level outputs.
5. The user retries or debugs failed steps.
